# Interactions Logic and Migration Implementation Plan

**Goal:** Finish the interactions design with persistent, collaborative page/project logic, code generation, and a safe migration from legacy workflows.

**Spec:** `docs/superpowers/specs/2026-11-13-interactions-design.md`.

1. Define and validate versioned logic documents, variable defaults, flow steps, and cross-scope name uniqueness; publish the schema and expose validated operations.
2. Add reversible Goose migrations and API model fields for `Project.Logic` and `Page.Logic`. Preserve existing data and existing uncommitted changes in both Go repositories.
3. Implement authorized, serialized realtime logic patches, consistent snapshots, persistence, per-page sequencing and project-wide broadcasts; reject collisions and malformed documents without applying them. Verify with multiple clients and concurrent edits.
4. Connect logic documents to editor history and runtime, expose variables/flows in authoring and the Logic rail panel, and handle rejection/rollback and deletion warnings.
5. Generate readable TypeScript for interactions, variables, and flows; test representative output and integration with the existing export pipeline.
6. Build a dry-run-first migration of legacy workflows using real handler fixtures. Report every unsupported action, preserve source records, and only apply explicit, transactional migrations. Remove legacy runtime only when migrated data has a safe compatibility path.
7. Run unit, integration, build, and unauthenticated browser checks across all three repositories. Do not mutate production data or automate Clerk sign-in. Do not push.

## Work in progress

- Implemented shared document validation and immutable variable/flow operations in `src/features/interactions/logic.ts`; the published schema contains Logic and variable definitions. Reserved variable names that expressions cannot read are rejected.
- Added Goose migration `00002_interaction_logic.sql` and API model fields in `/home/ghug/Code/Go/webbuilder.api.go`.
- Added unconnected server-side validation and a transaction-based Logic repository in `/home/ghug/Code/Go/webbuilder.realtimev2.go`. It checks read/write roles, locks the project row, validates names across pages, and was exercised against disposable PostgreSQL. It is not yet connected to websocket messages or page snapshots.
- Added a fail-closed, partial legacy handler translator and a pure migration planner in `webbuilder.api.go/internal/workflowmigration`. The planner groups workflows shared across elements into page/project flows and rejects an entire workflow if a link cannot be translated. Legacy template markers and malformed optional fields are rejected. No command, conflict checking against stored documents, or apply path exists yet.
- Added an expression compiler and emitted helper definitions in `src/features/interactions/codegen/expression.ts`, tested against interpreter behavior. It is not connected to a full interaction generator or export pipeline.
- Outstanding: design an atomic relationship between Redis page sequence/snapshots and durable Logic writes; wire authorized page/project messages and undo; build Logic UI and runtime plumbing; implement codegen and the migration command; verify all cross-client and migration flows. Existing websocket handlers appear to authenticate identity without checking project membership; address authorization before exposing new operations.
- Realtime now lives in the API repo (`internal/realtime`, mounted at `/ws`). It handles `logic:update`/`logic:sync` with write-role checks, per-page serialization, and project/page-scoped broadcasts.
- The Logic store (`logic-store.ts`) is bound to the websocket from `CollaborationProvider`: edits show at once, are sent as merge patches, and roll back with a toast if refused. Server documents replace local state once no edit is in flight. Undo/redo replays a change on top of collaborators' edits. Offline edits are refused. A merge patch cannot store `null` inside an object, so such changes (e.g. an object variable defaulting to `null`) are refused with a message.
- The preview route reads published logic from the public API (`/projects/public/:id` returns `logic`; `/pages/public/:id` returns each page's `logic`; drafts return nothing), via `snapshotFromServer`. Checked against a local API and database. Pages and project must validate together, otherwise the preview runs with no logic rather than half of it.
- Codegen is in the export. `codegen/interactions.ts` (`toCode`) emits a readable `interactions.ts`: a typed variable store, exported flow functions, one named async function per interaction, and a `bindInteractions()` that attaches them by `data-element-id`. Only the helpers a project uses are emitted. `/api/generate-code` accepts an optional `logic` (validated first) and returns `{ code, interactions }`; the component generator tags elements, no longer passes `settings.interactions` to the DOM, and calls `bindInteractions()`. The code panel has a Generated.tsx / interactions.ts switch. Tests type-check the output under strict settings with every verb, and run it in a fake DOM against the interpreter's behaviour.
- Differences from the interpreter, deliberately: no run log; `animate` uses the Web Animations API instead of the preview's CSS classes; `code` steps still use `new Function`; `mouseenter`/`mouseleave` use the native events. Toasts import `sonner`.

- Added a read-only PostgreSQL migration dry-run command in `webbuilder.api.go/cmd/workflow-migration`. It reports unsupported workflows and destination conflicts from a consistent snapshot; it has no apply mode. The old event hook is still active, so a future apply path also needs a cutover that avoids executing both old and migrated workflows and handles realtime caches.

- Added a transactional, idempotent local-only apply mode and per-link editor cutover markers. The source tables remain intact. Apply requires an offline editor/realtime service and reconciled Redis page caches; this cross-service condition is not enforced by PostgreSQL. A local PostgreSQL database was initialized; one workflow and its owner and project were copied from production through a read-only source transaction. Apply reported the workflow has no element links and did not migrate it.
- The Logic panel now asks for confirmation before deleting a variable or flow and lists references in loaded elements and logic documents. Interactions on other pages are not loaded and may contain additional references; the dialog says so. Rejected remote edits already roll back and show a toast. A browser fixture checks the confirmation, cancel, deletion and undo; it uses a stub for editor elements and does not exercise a live collaborative session.
- Verification: the frontend production build and both Go repositories' test suites passed. API tests ran with isolated PostgreSQL schemas and disposable Redis. A WebSocket/PostgreSQL integration test verifies project updates reach clients on different pages, viewers cannot write, and reconnecting reads the persisted update. The WebSocket test uses an in-memory element document repository, so it does not establish an end-to-end Redis/editor deployment check.
- A combined API server check now uses disposable PostgreSQL and Redis: six client collaboration tests passed; after server restarts and cache clears, element trees and logic reloaded from PostgreSQL; access checks rejected a viewer's write and an outsider. The check exposed page persistence and snapshot schema defects, fixed in the API repository with migration `00003_snapshot_page.sql`. That migration has not been applied to existing databases. Clerk authentication and an authenticated browser editor remain untested.

## Review fixes (2026-11-14)

- Client and server now agree on what a logic document may store: anything without error-level issues. Empty step fields and unparseable templates are incomplete drafts and are kept; only that step fails at run time. Both validators check the same fixtures (`tests/fixtures/logic-parity.json`, `internal/realtime/domain/logic/testdata/parity.json`).
- `GET /pages/public/:projectid/:pageid` returns 404 unless the project is published and the page belongs to it.
- `/api/generate-code` rejects element interactions with errors; codegen whitelists toast kinds, skips unknown events and strips comment terminators, line and paragraph separators from comments.
- Logic documents carry a revision (`00004_logic_revision.sql`); clients drop documents older than the one they hold.
- The `?devUser=` override and the startup `ALTER TABLE` were removed from the API's realtime copy.
- Not done: multi-instance project broadcasts, soft-deleted pages in name checks, client-supplied `pageId` on `logic:update`, the pending counter after a rebind, and undoing the deletion of a flow with an incomplete step. Migrations 00002–00004 have not been applied to existing databases.
